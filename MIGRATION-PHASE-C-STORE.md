# Phase C increment5 — atomic durable continuity references

[Continuity storage](src/continuity-store-v02.ts) adds separate STRICT policy/checkpoint/job-reference tables using the existing MemoryStore single SQLite connection and its immediate transaction owner. The constructor is not invoked by the main plugin yet; only synthetic tests create these tables. No personal-memory source, raw body/tool args/results, provider verdict, task success or permission is stored.

Explicit session/opaque-project admission starts denied. Policy updates bump a monotonic generation, cancel all pending references and delete the checkpoint atomically, including project rebinding. Reenable never resurrects old jobs. Enqueue validates a strict bounded structural envelope, exact ownership/current generation/allowed policy in the transaction, refuses cut regression or same-cut source conflict, and writes checkpoint + deduplicated source/trigger reference together. Reads/listing require matching current allowed project/generation; listing is bounded100.

The trusted caller MUST bind/recover against canonical source before enqueue. Strict schema is not source proof, human authority or consent. This is a persistence primitive, NOT the finished continuity owner/summary worker; it has no claim/lease/provider/ack/success workflow, remote API or automatic trigger subscription. Trigger strings pause/finish are references—not verified human actions. This module itself cannot resolve native human intent, project membership or per-session privacy rules.
