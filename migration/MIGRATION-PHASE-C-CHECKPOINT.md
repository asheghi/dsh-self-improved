# Phase C increment4 — canonical-bound cold checkpoint recovery

[Checkpoint helper](../src/continuity-checkpoint-v02.ts) creates a detached structural envelope bound to format, native session id, immutable header hash, inherited fork floor, actual SDK watermark and canonical source-prefix hash. It stores no source bodies. Recovery requires COMPLETE contiguous canonical events, validates envelope/schema, then independently rederives the stored prefix and compares its structural state. Even schema-valid forged human coordinates, cleared pending actions or delegated flags cannot become authority. Valid cache prefixes seed the actual native restore and the tail advances once; rejected cache is discarded and the complete source is refolded, never replaced with invented empty progress.

This conservative COLD recovery is O(full canonical source), including transient hashing; it is not a zero-I/O cache optimization or global history-size cap. Warm projection updates remain native incremental drive. No full history enters a provider prompt. Source hashes detect mismatches against the current canonical input, not an external golden root against a same-OS attacker who also consistently rewrites canonical history.
