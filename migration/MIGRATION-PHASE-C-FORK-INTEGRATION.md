# Phase C fork admission: minimal integration plan, not implementation or acceptance

This document records the C-specific architecture plan; it does not alter shared Phase A/B capture helpers, implement Continue, or confer model/task permissions. Existing v2 structural owner/source/preview paths remain conservative for ordinary native forks. Separately, the unregistered v3 capture/preview prototype now classifies a real native fork only as a candidate, then requires full child-to-root verification; this is not production admission or a model/task permission.

## Current constraints and concrete incompatibility

The [pure projection](<../src/continuity-projection-v02.ts#L39-L63>) initializes `delegated` through shared `isDelegatedHeader`, which treats a native `parentSession` as delegated. Own user input in an ordinary fork therefore never updates `lastHumanSeq`. The [owner](<../src/continuity-owner-v02.ts#L29-L49>), [source verifier](<../src/continuity-source-v02.ts#L16-L30>) and [preview](<../src/continuity-preview-v02.ts#L49-L75>) independently deny the same header. Changing only one guard cannot safely admit forks and would leave inconsistent cold/live behavior.

The [standalone ancestry verifier](<../src/continuity-ancestry-v02.ts#L30-L98>) already validates real native child/parent ownership, projects, inherited markers/prefix equality, delegation markers, missing ancestry/cycles/depth, and observation lifetime. It is **identity only**, not intent/consent/continuation authority. Its current `proofHash` includes child and ancestor **full current** `asOfSeq`/`sourceHash`; a legitimate parent append changes that proof even though the fork's immutable original copied prefix is unchanged. Do not store/compare that current full-source proof hash as a historical fork job's immutable authorization anchor.

## Stable historical lineage binding

An isolated, strictly validated **historical fork binding** is implemented in [the ancestry module](../src/continuity-ancestry-v02.ts), without changing the standalone current full-observation proof's meaning. Binding format 2 contains the selected child's immutable header hash, inherited floor and selected historical cut, plus an ordered edge list. Each edge records child/parent session identity hashes, normalized immutable header hashes, both inherited floors, and the parent prefix cut/hash **actually copied by that child**. It includes project ID, explicit binding version and root termination identity, using the audited canonical digest/header helpers; only omitted native `delegationDepth` becomes exactly zero.

For edge child `C` to parent `P`, copied bytes are exactly `C.events[0:C.inheritedEventCount]`, and the matching parent bytes are `P.events[0:C.inheritedEventCount]`. Their stable prefix cut is `C.inheritedEventCount - 1`, including `-1`/the canonical empty-prefix digest. Exclude `C`'s CHILD-owned `session/end-seed` marker and synthetic fork closers from this parent-prefix comparison. The child's **selected-cut source digest** separately binds its own marker/closers/events up to the job cut.

For a nested chain, derive the next edge from the parent's immutable inherited floor/parent header, not the descendant's selected cut or the parent's latest tail. If the descendant fork copied only part of an ancestor's inherited region, still validate that ancestor's **own** complete native seed descriptor and its own parent edge. Do not invent ancestry from the shorter descendant prefix. Record every relevant edge prefix, header, floor and link; neither an unbound root termination nor a missing parent may be silently omitted.

Revalidation reads each node as a complete canonical native observation and applies all current native/ancestry structural checks. Complete reads are needed to detect corrupt vocabulary/ownership/seed descriptors; stable comparison hashes only immutable header/floor/link coordinates and edge-relevant prefixes. Full current cursors and whole latest ancestor body hashes are diagnostic/read-validation coordinates, **excluded from historical binding equality**. Thus a valid append outside those prefixes does not invalidate an old job. An altered original prefix, replaced header/floor/link, delegated/unknown ancestor, missing parent, or corrupt current native read still refuses. This is not a golden root against coordinated malicious history rewriting.

Do not let a supplied binding authenticate itself. A private Host module constructs a detached verified lineage value only after native query validation. Consumers compare its freshly computed stable binding with the stored job binding. No `allowFork` flag, model declaration, arbitrary caller hash, fake work token, or wire ancestry blob substitutes for verification.

## Minimal changes by layer

### Pure projection and native schema

The isolated [v3 projection](../src/continuity-projection-v03.ts) uses state version **2** with structural `lineageKind: root | fork-candidate | denied`. Its strict native-header classifier is separate from the shared A/B helper: known `origin`, nonzero or malformed depth deny. A parent-linked seeded native header is only a **candidate**, never ancestry-verified by the synchronous pure fold. The subsequent v3 ancestry verifier validates the full parent chain; this structural label alone never grants action admission.

For candidates, record direct own native human seqs only at/above `inheritedEventCount`; injected/coordinator/tool/model sources and inherited events remain non-authoritative. `lastHumanSeq` in a candidate means structural evidence to be independently verified, not permission. Keep pending/result limits and uncertain tool outcomes unchanged. Retain or replace `delegated` consistently with strict state refinements; it must never accidentally suppress ancestor delegation checks or imply a candidate is verified. Projection registration must remain pure, with no asynchronous query, storage/provider call or externally injected admission boolean.

### Source identity, checkpoint and durable job schema

The isolated v3 prototype uses checkpoint envelope **format 2** and source-composite **sourceBindingVersion 3** for its state/lineage semantics. The existing `sourceBindingVersion: 2` root encoding is legacy decode/archive only and is not active job admission after cutover. Keep version namespaces explicit: the isolated envelope codec stores outer `checkpointFormat: 2`/`sourceBindingVersion: 3`, a named `lineage` object with `format: 2`/`bindingVersion: 3`/`bindingHash`, plus distinct `source_binding_version`, `selected_source_hash`, `lineage_format`, `lineage_binding_version`, `lineage_kind`, and `lineage_hash` columns. Never flatten both numeric `3` versions into one unqualified `bindingVersion`. The pinned source-hash recipe is canonical `digest({sourceBindingVersion:3,sessionKey:digest(sessionId),projectId,cut,lineageKind,selectedSourceHash,lineageHash})`; the explicit selected hash must equal `lineage.child.selectedSourceHash`, and `lineageHash` equals the nested `bindingHash`, which binds the normalized immutable header, inherited floor, canonical selected event prefix, and ancestry. Root bindings have an explicit root variant, not nullable ancestry that could stand for an unverified fork. Review of this isolated recipe is still pending.

Persist the bounded, body-free binding metadata with the checkpoint/job using an explicit compatible schema migration or new tables. Store its version/hash alongside the job source hash; expose it in detached claim/reference DTOs and compare it in `isCurrent`, settlement, handoff insertion/read and preview ownership checks. Even if sourceHash transitively includes lineageHash, explicit version/hash fields prevent a caller from confusing root/legacy/current representations. Cap ancestors/serialized metadata; a cap on ancestry depth is not a cap on full source memory.

Existing experimental state-v1/envelope-v1/binding-v1-or-v2 jobs must fail closed under fork admission. Old cache rows may refold native source into state v2, but cannot silently rebind existing jobs, resume permission, or rewrite same-cut references. Do not relabel old handoff payloads as new ancestry-verified outputs. Cancellation/version-fencing and any authorized new job creation must be explicit and tested, preserving current privacy denials. A deployment-specific migration policy remains a review prerequisite.

### Legacy cutover and deployment policy

**Proposed isolated Phase C decision; not permission to migrate a profile or production store.** Do not convert a legacy job into a lineage-aware job by recomputing hashes or deriving ancestry after the fact. At the explicit schema boundary:

1. Quiesce the old worker runtime and wait for accepted jobs to settle before changing schema; then use the same `MemoryStore` owner and one IMMEDIATE transaction for schema-version checks, versioned-field migration, and durable fencing. Verify the exact supported prior schema before the first write. The existing v2 deny-fence is not itself a versioned migration preflight, even after its exact-layout hardening; see the remaining scope below. Unknown, partial, or mixed versions abort before mutation and keep continuity default-off.
2. Cancel every still-pending legacy job, fence its policy generation, invalidate its continuity checkpoint, and make any extant work lease non-settleable. This intentionally retires pending v1/v2 work rather than guessing root authority; there is no automatic re-enqueue from old session history.
3. Keep old handoff payloads explicitly `legacy`: archive-only, untrusted, uncertain, and never eligible for preview/Continue or new worker input. Do not backfill a lineage hash or relabel an old sourceHash. Preserve old records only for the existing untrusted archive contract.
4. Native projection caches are derived state: a `stateVersion` mismatch may cold-refold from a complete canonical native log into state v2. That rebuild cannot restore a cancelled job or grant new intent. The plugin-owned durable checkpoint/job rows are separate and follow the cancellation rule above.
5. After cutover, all newly created jobs—including root jobs—use checkpoint format 2 and sourceBindingVersion 3 with an explicit discriminated lineage variant (`root` or verified `fork`); a missing lineage value is never shorthand for root. The old sourceBindingVersion 2 representation is legacy decode/archive only, not active work admission. Re-enqueue requires current policy and a new eligible human boundary.

This deliberately drops queued experimental work while preserving archived notes. Any migration against an active profile or production store requires separately approved backup, dry-run, quiescence, rollback, and data-retention planning; it remains outside isolated Phase C acceptance. Independent review must approve the DDL/version fence before deployment. The current [v2 policy fence](../src/continuity-store-v02.ts#L106-L145) now checks the shared canonical DDL, ordered column/type/null/default/PK/hidden metadata, STRICT/index shape, and rejects custom main/TEMP indexes, triggers, or TEMP name shadowing before main-qualified denial writes. Its [regressions](../scripts/test-v02-continuity-fence.mjs) cover the exact-v2 path and no-write refusal for partial/reordered/case-variant/extra-column tables, altered/case-shifted CHECKs, custom indexes, main/TEMP triggers, and TEMP-only/shadow tables. Startup still invokes this fence before the v2 store constructor DDL ([ordering](../src/index.ts#L708-L805)). This hardens only the existing v2 policy/checkpoint/job trio; it is not itself a v3/versioned migration, and normal runtime dispatch remains v2-only. The read-only classifier, v2 row preflight, strict marker/human-boundary contracts, six v3 active DDL templates and epoch-3 fingerprint, policy/boundary guards, exact archive-sidecar validation, fresh-only schema owner, and a gated one-shot offline v2 cutover writer now exist with isolated regressions, as detailed below. They remain unwired into normal Host startup; no file-backed, active-profile, or production migration and no Phase C acceptance occurred. A separate `continuity-projection-v03.ts` prototype supplies a strict state-v2 fold and native-header `root`/`fork-candidate`/`denied` classifier; it remains unregistered, and fork-candidate is not ancestry authority. The isolated `continuity-source-v03.ts` producer now re-reads native child-to-root ancestry and requires the supplied selected observation to match before composing the `continuity-envelope-v03.ts` checkpoint DTO. Its `isContinuityV03JobSourceCurrent` helper compares a strict pending job anchor with a fresh recomputation at that historical cut, so a newer checkpoint does not invalidate older pending work. The codec and row preflight pin version namespaces, selected-source/composite hashes, state/lineage payloads, and job/work/handoff anchors. The new DDL-free `continuity-work-v03.ts` store now claims, checks currentness, and failure-settles v3 leases inside the same-store IMMEDIATE transaction seam, after exact-schema and row preflight; predicates bind current policy generation, checkpoint progression, full job anchors, work token, deadline, and attempts. Its `completeWithFreshSource` path now rechecks native historical source and the SQL lease/policy after async reads, then inserts a strict handoff and marks work completed in one immediate transaction; this remains an isolated store API, not a provider dispatcher or user-intent admission, and is unwired from Host with independent review still open. The fingerprinted v3 schema is continuity capture/worker only: it contains no Continue/action journal. Because the Host user-only intent and idempotent dispatch APIs remain unverified, Continue/action admission stays off; if ever implemented, its journal must be added under a reviewed schema epoch/fingerprint before admission.

### Schema epoch and supported cutover states (fresh owner and gated offline writer implemented; no file-store cutover run)

`MemoryStore` construction first runs its own legacy backup, general schema setup, v1/v2 marker migrations, and `repairConsistency`; the continuity fence runs only afterwards ([constructor](../src/storage.ts#L192-L200), [startup order](../src/index.ts#L708-L727)). The separate `repairEpisodeConsistency` runs later ([separate repair call](../src/index.ts#L930-L938)) and is not a continuity-preflight step. Thus “preflight before DDL” below means before any **continuity-owned** DDL or row mutation, not before generic `MemoryStore` initialization. The exact current [v2 fence](../src/continuity-store-v02.ts#L106-L145) covers only `continuity_policy`, `continuity_checkpoint`, and `continuity_jobs`. `ContinuityWorkV02` and `ContinuityHandoffV02` currently create `continuity_work` and `continuity_handoff` in separate transactions ([work DDL](../src/continuity-work-v02.ts#L27-L37), [handoff DDL](../src/continuity-handoff-v02.ts#L29-L43)). The archive reader creates/migrates nothing and marks output `untrusted`, `uncertain`, and `usageEligible:false` ([archive contract](../src/continuity-archive-v02.ts#L9-L20)). `continuity_summary_policy` and `continuity_summary_human` are separate consent and fresh-human-watermark ledgers ([policy](../src/index.ts#L737-L779), [watermark](../src/index.ts#L822-L868)); preserve them, and never reset the existing watermark to reuse an old human event. Native projection cache state is DSH-service-owned and may only cold-refold from complete canonical history.

The fresh-only `ensureContinuitySchemaV03(store)` now classifies Empty and atomically creates the mandatory v3 core plus fingerprint marker; on exact v3 DDL it runs read-only structural preflight for policy/boundary/checkpoint/jobs/work/handoff rows, including strict version/hash/anchor validation. That preflight is not a comparison with live native source and cannot grant work, lineage, preview, or Continue admission. It refuses Legacy v2 at normal startup; the separate one-shot offline migrator is the only path that can convert it. `ensureContinuityWorkerPairV03` creates the optional pair atomically. These functions are isolated and not wired into startup. A separate DDL-free `continuity-policy-v03.ts` now offers idempotent `ensurePolicy` and explicit `setPolicy`: the latter advances generation, cancels pending jobs, fails running leases, and deletes checkpoints atomically; project moves purge the old active jobs/work/handoffs/checkpoint/boundary. Its private SQLite regressions cover no-op preservation, revocation/re-enable without resurrection, project purge, and transaction rollback. This persists only an already-authorized structural setting; it does not authenticate consent, update summary ledgers, or grant worker/Continue admission. Present summary ledgers remain unvalidated and cannot authorize body-worker admission. A historical boundary row behind the current policy generation is retained as non-authoritative metadata; capture must require allowed=1 and exact-generation equality. The complete versioned owner must dispatch and perform continuity DDL after `MemoryStore` construction but before the current v2 fence or any continuity store/worker/handoff constructor. It must use this same `MemoryStore` connection and own the entire continuity preflight/migration transaction; no continuity `CREATE TABLE IF NOT EXISTS` may run before classification. Mandatory active v3 tables are the schema marker, `continuity_policy`, `continuity_checkpoint`, `continuity_jobs`, and the new `continuity_v3_human_boundary` described below. `continuity_work` plus `continuity_handoff` are an optional inseparable pair: both absent before the summary worker is mounted, or both present with exact v3 DDL. V03 worker/handoff constructors are DDL-free; immediately before lazy worker construction, the same owner exposes `ensureWorkerPairV03`, which validates marker/core and then either creates both absent tables in one IMMEDIATE transaction, accepts both exact tables, or refuses a split pair. The old `fenceExistingContinuity` remains v2-only; dispatch to a v3 schema/policy fence instead, and never mount a v02 store/worker/handoff constructor against the active v3 tables. Call the Already-v3 result a schema-migration no-op. After that classification transaction, run a v3 structural revocation-only fence: unchanged settings leave `continuity_policy.generation` unchanged; current disabled/excluded/denied rows are fenced, pending jobs cancelled, and checkpoints invalidated. Startup reconciliation never grants or resurrects. A per-session automatic-capture grant is made only by the live owner after current structural consent and a fresh boundary. A privacy/Advanced consent change is a separate authenticated user-only operation that advances structural generation; neither migration nor Continue intent is consent. Reconcile summary-body consent only through its separate hardened owner before body-worker admission; its process-local body epoch may increment each boot, but it is not the structural generation or watermark authority.

Use an exact STRICT singleton marker table `continuity_schema_meta`: `id INTEGER PRIMARY KEY CHECK(id=1)`; `marker_format INTEGER NOT NULL CHECK(marker_format=1)`; `schema_epoch INTEGER NOT NULL CHECK(schema_epoch=3)`; `origin TEXT NOT NULL CHECK(origin IN ('fresh','v2-cutover'))`; `legacy_archive_state TEXT NOT NULL CHECK(legacy_archive_state IN ('none','jobs-only','jobs-and-handoffs','purged'))`; and `ddl_fingerprint TEXT NOT NULL`, constrained to exactly 64 BLOB bytes with an explicit NUL exclusion and a positive fixed-width lowercase-hex GLOB. Also CHECK that `origin='fresh'` pairs only with archive state `none`, while `origin='v2-cutover'` pairs with `jobs-only`, `jobs-and-handoffs`, or `purged`. Here `origin='fresh'` means a fresh continuity lane, not a blank MemoryStore. Require exactly one row; a marker table with no row is partial/unknown, not Empty. Any marker DDL or value-domain change requires an explicit `marker_format`/`schema_epoch` migration, never silent widening. Define that fingerprint as SHA-256 over the mandatory and optional-pair v3 table templates in ASCII table-name order: append a frame for the table name followed by a frame for its canonical DDL; each frame is a 4-byte unsigned big-endian UTF-8 byte length followed by those UTF-8 bytes. Canonical DDL uses the same rule as the current [DDL normalizer](../src/continuity-store-v02.ts#L49-L83): remove only the `CREATE TABLE IF NOT EXISTS` modifier, normalize whitespace outside single-quoted literals, and preserve literal bytes. V3 templates use bare ASCII identifiers and no comments; any other quoting form requires a reviewed canonicalizer/marker-format change. Include optional-pair templates even while the physical pair is absent. Exclude the marker table's DDL from its own fingerprint and validate the marker DDL separately; the fingerprint never substitutes for exact column/index/trigger/TEMP inspection. A future archive purge must be a separate explicit retention migration that removes the entire state-appropriate legacy sidecar set and atomically updates `legacy_archive_state='purged'`; partial purge is unsupported and absence is never silently inferred. Do not reuse `MemoryStore`'s generic `schema_state` / `PRAGMA user_version` marker: those represent independent storage migrations ([owner](../src/storage.ts#L485-L523)). The schema epoch is distinct from outer `sourceBindingVersion: 3` and nested namespaced lineage `format`/`bindingVersion`.

The continuity-object allowlist is closed and exact. Recognized main-table names are `continuity_policy`, `continuity_checkpoint`, `continuity_jobs`, `continuity_work`, `continuity_handoff`, `continuity_schema_meta`, `continuity_v3_human_boundary`, `continuity_jobs_legacy_v2`, and `continuity_handoff_legacy_v2`; the only independent main-table exemptions are `continuity_summary_policy` and `continuity_summary_human`. `continuity_work_legacy_v2` and every other `continuity_*` table are unrecognized. Each listed name is valid only as its expected main-schema table object; a same-name index/view/trigger is Refuse. Inventory every schema returned by `PRAGMA database_list` (main, TEMP, and all attached databases) before classification: any unrecognized case-insensitive `continuity_*` name or attachment (`tbl_name`), any TEMP shadow of an allowlisted main name, or any custom index/trigger on an allowlisted table is Refuse. Accept only exact per-table DDL and expected implicit autoindexes. The two summary ledgers are excluded from continuity DDL/data writes; the census still rejects their TEMP shadows and extra indexes/triggers. The separate summary-consent owner now lives in [continuity-summary-ledger-owner.ts](../src/continuity-summary-ledger-owner.ts#L159-L243): it validates exact main DDL/columns/indexes, rejects TEMP/attached shadows and direct/indirect triggers, and main-qualifies all reads/writes. The existing [summary-policy sync](../src/index.ts#L750) and [human-boundary claim](../src/index.ts#L806) use it; repeated worker consent boundaries recheck the schema. Private SQLite refusal snapshots and the native Loader suite verify incompatible schema/index refusal leaves consent rows unchanged and admits no body work. This closes only the summary-ledger schema subgate: v3 body-worker/preview admission, Host-authenticated source/intent receipts, and the remaining Phase C UX/action gates stay off. Do not claim the continuity migrator validates or repairs these ledgers. No wildcard/prefix exemption is permitted.

The preflight's read-only classification, inside the same store's IMMEDIATE transaction and before any continuity-owned DDL or data mutation, should support only these explicit states:

- **Empty:** no migration-owned continuity core, worker/handoff, legacy-sidecar, or marker objects in main/TEMP schemas. A store containing only independent summary-policy/human-watermark tables still counts as empty; leave those rows/tables untouched during classification and schema bootstrap. Empty is a classifier result, not an early return: within the same IMMEDIATE transaction, the version owner bootstraps the default-deny v3 continuity core with `origin='fresh'` and `legacy_archive_state='none'`, leaving the optional worker/handoff pair absent. After classification/bootstrap commits, run structural revocation reconciliation. Invoke the separate summary-consent owner only after its exact-shape/main-qualification gate is hardened; otherwise keep v3 body-worker admission off.
- **Legacy v2:** the exact canonical v2 core trio and no continuity marker or legacy sidecars; `continuity_policy` keeps the exact canonical v2 DDL in v3 by design and is updated in place only. If the policy DDL differs, refuse this cutover and require a separately specified conversion. `continuity_work`/`continuity_handoff` are either both absent or both present with exact supported v2 DDL. A split pair is unsupported: the old worker constructs these tables in separate transactions, so work-only can be crash residue. Never bless that partial state by constructing whichever table is missing.
- **Already v3:** exact v3 marker/fingerprint and every mandatory active table. `origin='fresh'` requires `legacy_archive_state='none'` and no v2 sidecars. For `origin='v2-cutover'`: `jobs-only` requires only `continuity_jobs_legacy_v2`; `jobs-and-handoffs` requires exact `continuity_jobs_legacy_v2` and `continuity_handoff_legacy_v2`; `purged` requires no legacy sidecars and is valid only after the explicit retention migration updates the marker. Retained jobs contain only cancelled old anchors; retained handoffs satisfy the renamed-v2 schema/anchor contract. There is no retained v2 work ledger. The active v3 `continuity_work`/`continuity_handoff` pair is independently both absent or both exact. Require explicit valid lineage fields on active jobs and no legacy handoff admitted as active work. This is a schema-migration no-op: leave the structural v3 generation unchanged on unchanged settings, then run revocation-only reconciliation for changed/denied consent or exclusions; never grant or resurrect from boot reconciliation.
- **Refuse:** unknown marker/version/origin/archive state, unknown continuity-prefixed object in main, TEMP, or an attached database; any TEMP shadow, marker/schema/fingerprint/archive-state mismatch, partial core or sidecar set, split worker/handoff pair, mixed v2/v3 active tables, case-variant names, altered DDL/columns/constraints, custom index/trigger, matching TEMP object, a legacy job still pending in an already-v3 state, or unsafe row data such as generation overflow, orphan/mismatched work or handoff/job anchors, malformed/oversized legacy payloads, invalid tokens/attempts/lease coordinates, or an unexpected `continuity_work_legacy_v2` sidecar. Ordinary pending jobs and running work rows are expected in exact Legacy v2: pending jobs are cancelled, and the entire operational v2 work ledger (including running lease rows) is dropped after offline drain; no failed-work status is claimed to persist. Valid durable v3 running leases remain recoverable under the v3 worker's lease rules. Return no cleanup claim and make zero continuity writes; keep continuity default-off.

Cutover is explicitly **offline**, not an online schema upgrade. The old runtime's accepted-task drain must reach actual settlement ([drain contract](../src/shutdown-v02.ts#L20-L51), [implementation](../src/shutdown-v02.ts#L138-L200)); then every old DSH Host process that can open this storage root must exit, with no other opener/provider call remaining. The current drain tracks only one plugin process and no cross-process lock was found; a shutdown deadline or SQLite `BEGIN IMMEDIATE` cannot stop another Host's already-running native query/provider call.

The v2 conversion runs only through the dedicated `scripts/migrate-continuity-v03.mjs` launcher, never normal plugin startup. It requires one each of `--offline-approved`, `--exclusive-owner-confirmed`, `--backup-confirmed`, and an absolute non-root `--store-root`; after consuming args into an opaque one-use capability, the launcher resolves and rejects a canonical filesystem root and requires an existing regular, non-symlink `<store-root>/memory.db` before dynamically importing `MemoryStore`. CLI authorization and path-validation regressions use no store/file-backed SQLite; the actual writer has only been exercised with private in-memory SQLite fixtures, never a file-backed store. The authorized callback is the sole opener: `MemoryStore` first performs its normal generic initialization, then `runContinuityV03OfflineMigration` does exact schema/row preflight, policy revocation, checkpoint/lease retirement, inert v2 archive creation, v3 DDL/marker installation, and same-transaction postflight; it closes and exits without mounting runtime/provider workers. The three confirmation flags are operator assertions only—the code cannot prove other Hosts/processes are gone or that a backup exists. Require the operator runbook's exclusive ownership, backup, dry-run and rollback planning. Start the normal new Host only after a successful migration/marker validation and separate Phase C acceptance. The gate must live above the plugin because generic `MemoryStore` initialization precedes continuity preflight; normal startup still refuses Legacy v2 and keeps ingress/worker admission off.

For recognized v2, use one IMMEDIATE transaction with this order:

1. Complete all read-only schema and row checks first. Verify every old policy generation is a safe integer below its increment limit; check work rows reference jobs with valid token/status/attempt/lease coordinates; and verify each retained handoff has exactly matching job anchors and a bounded strict-v2 payload. Generation overflow, orphan/mismatched anchors, invalid lease/token data, or malformed legacy archive payload aborts before the first write.
2. Set all old policy rows `allowed=0` and increment each generation exactly once; cancel every pending legacy job; delete old checkpoint rows, then drop/recreate the checkpoint table with v3 DDL.
3. Rename the old job table to `continuity_jobs_legacy_v2`. Only when the exact supported v2 worker/handoff pair existed, rename its handoff table to `continuity_handoff_legacy_v2`; then, when the pair existed, drop the old `continuity_work` table including any running lease rows (if the pair was absent, there is no work table to drop); work/lease state is not part of the archive contract and is not retained.
4. Install fresh active v3 job DDL, the mandatory empty `continuity_v3_human_boundary`, and the marker with `origin='v2-cutover'` plus `legacy_archive_state='jobs-only'` or `'jobs-and-handoffs'` according to the preflighted old optional pair. Keep the active v3 work/handoff pair absent until the same schema owner creates both atomically.
5. Commit. Any later DDL/row error rolls the entire transaction back; no old token may settle after commit.

Preserve legacy job anchors and handoff payload bytes unchanged. Replace the unversioned V02 archive read with a v3 adapter that branches on marker `origin`/`legacy_archive_state`: `fresh`, `jobs-only`, and explicitly `purged` return an empty legacy archive; `jobs-and-handoffs` reads only `continuity_jobs_legacy_v2` plus `continuity_handoff_legacy_v2`, validates their renamed-v2 schema and exact anchors, strictly parses v2 payloads, and emits only cancelled, untrusted, uncertain, non-usage-eligible items. Never send a lineage-bearing v3 payload through the strict v2 archive parser; never recompute a legacy lineage hash, relabel an old `sourceHash`, or enqueue replacement work from session logs. Ordinary forks remain denied until the full native lineage path is implemented.

#### Post-cutover human boundary

The old [owner](../src/continuity-owner-v02.ts#L22-L50) reconstructs `lastHumanSeq` from a complete historical observation, while the [runtime](../src/continuity-runtime-v02.ts#L14-L35) invokes capture at `turn/end`; after deleting the old checkpoint, a later turn/end could therefore enqueue from pre-cutover user history. A fresh human boundary cannot be inferred from that projection coordinate. Make `continuity_v3_human_boundary` a mandatory empty-on-cutover ledger, separate from body-consent-gated `continuity_summary_human`. The event adapter must be verified non-replaying; if its event mode can replay hydration/history, require an explicit live-event cursor/flag or keep admission denied. Populate it only from a post-migration native post-commit `user/message` append with `surfaceOp='append'` ([worker filter](../src/continuity-worker-v02.ts#L70-L83)), at/above the inherited floor, while current structural policy/exclusions allow, and only when v3 provenance proves direct live human ingress, non-injected origin, and verified root/ordinary-fork ownership using Host-verified request/header provenance. The existing [projection filter](../src/continuity-projection-v02.ts#L58-L63) is only a necessary candidate check: `source.kind === "user"` alone is insufficient because a model-authored SubAgent prompt can carry it ([source audit](../src/compat-v02.ts#L66-L77)). 6. Revocation/exclusion/project/generation/summary-route epoch changes during each child/ancestor await, provider hold and target/source preview refresh refuse; revoke/re-enable ABA is caught. Final token replacement/expiry equality/lineage-anchor drift cannot commit, and same-owner transaction rollback creates no acknowledged handoff.
7. Provider requests contain bounded own child excerpts only, with no parent body/session ID/proof upload; forged/output-extra/task-permission prose is rejected or remains literal uncertain extractive evidence. Preview/worker do not invoke Agent/follow/goals/prompt/Continue surfaces.
8. Existing A/B capture/privacy/delegation suites remain unchanged and passing; root continuity/checkpoint/worker/source/preview/ancestry portability tests remain passing. Independent review must explicitly cover any schema migration and all changed C header guard call sites before opt-in main integration.
9. Continue receipt: `source.kind === "user"`, event text, provider text, or an agent tool alone cannot mint authority. Only an authenticated user-only UI request with Host-verified provenance and verified target/fork ownership may issue a Host-generated `intentId`/`intentSeq`.

   - **Forged issuer:** test denial for non-user/unauthenticated contexts and forged or mutated client-supplied receipt fields, intent IDs/sequences, or nonces.
   - **Blank target/policy:** a blank/new target with no target `user/message` or `turn/end` must still support explicit Continue when its Host-resolved empty/current cut, lineage, and policy pass. Test that a missing target or consulted-ancestor policy row bootstraps default-deny, an explicit applicable consent produces a current generation, and the Continue click never grants consent.
   - **Capture independence:** exercise capture-first (a previously consumed target event does not gate the UI intent) and UI-action-first on a blank target (no freshness row required); the receipt never reads or changes the freshness row or `last_enqueued_human_seq`.
   - **Binding/replay:** bind target identity/project/header/floor/cut/root-or-fork lineage and target/ancestor generations; bind selected source/job/handoff, source lineage, and source/ancestor generations; target/source drift denies. Test DDL `UNIQUE(intentId)` and `UNIQUE(issuerEpoch,intentSeq)`, plus serialized IMMEDIATE actionKey exclusion; actionKey remains reserved after Agent run completion across target-cut changes, so the same stable target/source job generation cannot be continued twice, while a new target or source-job generation can. Only proven `failed_no_effect` with no Session event/Agent effect releases the key.
   - **Recovery:** test double-click/concurrent replay, one-shot nonce burn, <=30s expiry, process/plugin restart, and crashes before native append, after append/before state update, after event commit/before Agent dispatch, and after dispatch/before state update; recovery must find/reuse the same event/run ID without duplicate effects.
   - **Drift/revocation/native log:** test target-cut/source/job drift, changed selection, and revocation before append (`failed_no_effect`, key releasable) and after append for target/source/lineage drift or revocation (`cancelled_after_event`, no Agent dispatch, key retained); A mismatch rejected before committing the `pending` record creates no action row. A later recovery mismatch retains the already-committed row as `failed_no_effect` (and releases the key only after proving no event/effect) but creates no model-visible context or Agent effect. Ordinary Session listeners, replay/resume, and restart must leave pending, committed-but-undispatched, or `cancelled_after_event` context inert and must never activate Agent outside the action owner; `agent_dispatched` recovery must observe the same run ID. A successful action commits its continuation through the supported native Session event/inbox path before Agent activation; crash/retry with the same `intentId` is idempotent and never starts Agent before that event is committed.

## Honest remaining limitations

This is a design proposal based on current source, not an implemented gate or execution evidence. Ancestry and historical binding are source identity, not external side-effect verification or user authorization. Complete native reads retain O(full-source) memory/time; bounded ancestor count is not global body boundedness. Multiple source acquisitions are not one global snapshot; immutable headers/prefixes plus cancellation/policy checks define the permissible point-in-time scope. Missing source refuses rather than reconstructing authority from a saved projection. Current Host/Client Cordis Inspect catalogs have not identified an authenticated user-only UI route, Host intent-sequence facility, or idempotent native Session/Agent dispatch contract; until those actual APIs are verified, Continue/action admission remains off. Full main-host restart, browser UI acceptance, native-fork Continue and overall Phase C acceptance are not established here.

- [Projection and registry](../src/continuity-projection-v02.ts#L10-L63) [schema/registration](../src/continuity-registry-v02.ts#L36-L75): state version 1 is strict JSON, host-only, and cacheable.
