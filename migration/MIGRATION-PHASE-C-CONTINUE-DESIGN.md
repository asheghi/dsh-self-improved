# Phase C — explicit Continue design (not implemented or accepted)

## Decision

Offers and previews are cold, read-only operations. A selected handoff is orientation, never a goal, permission, successful-action verdict, or replacement history. The initial safe action is **Review selected history**, not an automatic model turn. No timer, offer-list render, generic “continue” matcher, settings navigation, or replay opens/resumes an Agent.

**rc.2 has no discovered dedicated Remote `continue` or no-activation native navigation API.** Existing cold reads can implement the preview. Native history opening via `follow` activates a cold Agent; strict no-background/no-provider behavior across composed plugins is not established. Do not invent `session.continue`, `sessions.select`, or a `noWake` flag. Explicit native opening is a separately confirmed option only after its acceptance tests establish the deployment's no-unrequested-turn behavior.

## Verified native route and important caveat

Live Host Cordis Inspect `Service.listService` exact contracts read for `sessionController`, `sessionQuery`, `agents`, and `goals` (rc.2). Client Service discovery timed out; installed public Client declarations were read as fallback, **not live navigation verification**.

- Host `ctx.sessionQuery.observeSession(sessionId, {signal, projectionMode: 'none'})` returns caller-owned `SessionObservation`: header, inheritedEventCount, contiguous events, cursor; dispose in finally. It does not make the Session live. `filterSessions([{kind:'cwd',values:[verifiedCwd]}], signal)` is an optional native candidate catalog; it lists metadata, not evidence of unfinished work.
- Host `ctx.sessionController.inspect(sessionId, signal)` is explicitly nonactivating. Existing generated Remote `ctx.remote.session.page({address:{kind:'session',sessionId}, throughSeq, beforeSeq?, maxMessages?, turnWindow?}, signal)` is cold-safe message-aligned history paging. Obtain throughSeq from a validated source cut, never a client-invented cursor. `ctx.remote.session.projections({sessionId}, signal)` also reads without activation.
- **Do not use `ctx.remote.session.follow` for an inert preview.** Installed [controller implementation](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L1521-L1527>) retains a prepared observation after yielding the opening snapshot; [promote](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L2899-L2923>) asynchronously resolves/resumes its Agent. Aborting the browser stream is not proof that this detached promotion was cancelled.
- Native `ctx.agents.resume({resumeSessionId, agentOptions?, setup?, signal?})` creates/publishes a live Agent. The core ReactLoop starts idle ([constructor](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L774-L789>)); it does not itself call followup on construction. However publication announces lifecycle events and composes other plugins. Thus “activates core Agent” is not identical to “requests model”, but it also is not a deployment-wide no-background-work guarantee.
- Public Client `ctx.sessions.retain(target,{source,signal?})` starts initial history opening; `using` retains through settlement. It is **not inert preview or navigation**, and navigation belongs to view owners ([contract](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-api-session-controller/lib/types/client/contract/sessions.d.ts#L42-L60>)). No live Client navigation method has been verified. Do not import private Client packages into this plain-JS plugin to bypass this gap.
- Later, only a separate explicit human Send uses native `ctx.remote.session.prompt({requestId,sessionId,mode:'queue',content,clientTimeZone?},signal)`. This resumes/adopts the addressed Session and calls `agent.followup` ([implementation](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-api-session-controller/lib/index.js#L850-L899>)). Request acceptance is not task completion; cancellation is checked before admission, not guaranteed turn rollback. No plugin-generated prompt is submitted on selection.
- Native goals are session-log authority. `ctx.goals.resume(agent,{id,revision})` rearms; it must NEVER be called by offer/preview/selection. Goals default disarmed on `agent/created` ([implementation](</home/bahman/github/dsh-v0.2/node_modules/@deepseek-ai/dsh-goal/lib/index.js#L594-L595>)). Human confirmation for history orientation is not goal-resume authorization. Leave native goal controls and their revision checks intact; do not copy a source goal into the new target.

## Proposed plugin business surface — names are NEW design, not runtime methods

Extend the existing `selfImprovedMemoryUi` / `selfImproved` typed Remote Service, not Config writes or a new event type. Proposed unary methods: `continuityOffers(targetSessionId, signal)`, `continuityPreview(targetSessionId, jobId, signal)`, `prepareContinuitySelection(targetSessionId, jobId, expectedCut, signal)`, `selectContinuityHistory(targetSessionId, jobId, authorization, signal)`. Use strict bounded request/result codecs mirrored in the plain-JS client descriptors; explicitly declare trailing cancellation parameter `signal` and test actual Gateway injection. Optional unavailable SDK/Remote dependencies return a visible unsupported reason, not fake success.

Read offers: authenticate Gateway invocation; obtain caller peer from server `ctx.invocation`, never payload. Resolve exact current target native header without resume, derive opaque project from `projectKeyFromCwd`/`opaqueProjectIdFromKey`, then enumerate `ContinuityHandoffV02.list(projectId)` and current structural work. Bounded candidates require current same-project eligible policy and source native verification; deduplicate a source/fork lineage rather than promoting inherited evidence into separate unfinished tasks. Current handoff list is at most50 admitted rows; work list at most100. Neither processing-completed nor turn-completed means task finished. Label list completeness honestly (no cursor/pagination guarantee from current primitives).

Preview and selection: acquire fresh owned observations of target/source; before and after each await check caller cancellation, plugin disposal, exact native IDs/cwd/project, session/project exclusions, delegation refusal, current generation and selected job/cut/hash. Recover the historical selected source via `continuitySourceAtCut` + canonical projection/binding; compare persisted composite sourceHash (header + inherited floor + prefix), not newest checkpoint. `verifyContinuityWorkSource` is currently typed to a running work claim: **do not fabricate a UUID/token/lease to reuse it for completed handoffs**. Add a pure completed-reference verifier sharing the canonical algorithm. Own-human evidence must be at/above inherited floor; a fork inherits context but not independent support. A stale selected cut may still be valid orientation, but show newer-source-available; never silently substitute latest notes/history.

Selection is user-only. Reuse the one-shot exact-args/peer-bound ledger pattern with a NEW operation vocabulary; bind target/source IDs, project, job, generation, cut/hash, TTL, and requested mode. Consume token once; reread policy/source before returning a cold-preview SessionAddress. A boolean `humanSelected`, typed source.kind='user', or nonce alone does not prove a physical human click. Authorization is the authenticated trusted operator lane plus no agent-tool/command exposure for authority-granting selection; peer/token only prevent replay/rebinding. Existing peers are logical shared operators, not physical browser isolation. Default deny missing invocation, unknown peer policy, unknown source, absent cwd, cross-project, excluded, delegated, inherited-only, stale/forged/corrupt, cancelled, unavailable capability. No model-facing Continue tool and no ambient initiator substituted for subject authorization.

The result is a validated cold-history address plus bounded uncertain orientation, NOT injection into an Agent inbox, a task start, or native navigation. It may prepare a **local draft** of human-authored continuation intent; generated notes are visibly separate quoted evidence, never represented as the user's new assertions. The user can explicitly choose the original source Session to retain native history. Continuing within the new current Session is a separate transfer-of-context option; do not pretend it inherits native history. It needs explicit reviewed context admission with attributed logged native context and bounded input, whose API is a later integration gate. Fork requires separate human choice and native `session.fork({sessionId,atSeq?})`, which creates a new Agent; neither offers nor preview calls it. Do not restore source approvals, queued actions, schedules, or goal activation.

## Privacy, paused/off inspection, and wording

Separate **operator saved-data inspection** from **future model-use eligibility**. [Current handoff read/list](<../src/continuity-handoff-v02.ts>) joins allowed current policy and completed processing, so it hides denied rows; [work inventory](<../src/continuity-work-v02.ts>) is not an off/paused archive browser. Do not lift those joins to make a revoked handoff eligible again. Existing [business dependency](<../src/business.ts#L150-L160>) already allows inert inspection while the master switch is off. Add a separate bounded authenticated project-scoped archive-read operation for saved continuity metadata, independent of capture/provider enablement, with current row scope and explicit saved/deleted/revoked/derived-unavailable labels. Generation mismatch remains ineligible for Continue/context use. Hard exclusions/purge must not be bypassed by auto offers; content inspection in a private/excluded scope needs separately defined explicit operator authorization, not a project ID supplied by the browser. No source reread/provider call on archive listing. Native history stays inspectable through its own host authorization; paused plugin is not permission to recreate derived content.

Suggested copy: “History preserved”; “Partial handoff generated at event …”; “Processing complete—not proof the task is finished”; “Unverified external action—check its actual state before repeating”; “Review selected history (does not send a message)”; “Opening the native conversation may activate its Agent; no new message will be sent by this action.” Do not promise no composed background work without evidence. Notes are untrusted quotes, never rendered as HTML/instructions or executable next steps. Paused/off banner states no capture, synthesis, provider send or automatic continuation; saved-data controls remain available.

## Acceptance required before implementation is accepted

Synthetic native cold/prepared/live history tests must measure no Agent creation, goal rearm, tool execution, provider calls, schedules or followups during listing/preview/selection; cancel held source reads and dispose leases exactly once. Race tests cover policy generation, exclusions, target/source project move, corrupt/missing old cut/hash, selected row deletion, fork inherited-only and unrelated project. Challenge tests cover rebind/replay/expiry/missing operator; agent cannot call user-only selection. If explicit native opening is enabled, test prepared follow activation separately, core idle behavior, composed creation listeners, outstanding inbox and schedules, human confirmation, unload/cancel/promotion ownership; this cannot be inferred from core constructor alone. Later human prompt/requestId replay must use native route and not duplicate an external action.

Mounted browser gates remain pending: keyboard/narrow/light-dark, conflict/unsaved draft retention across new Sessions destination, focus return, cancellation/stale response discard, uncertainty and revoked/paused inspection states. No profile install, GUI change, production read/write, model call or Phase C acceptance occurred for this design. Only this new document was authored for the original design task.
