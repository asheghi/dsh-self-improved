# Phase C isolated native-source process restart gate

## Scope

The [new fixture](<../scripts/test-v02-continuity-host-restart.mjs>) starts **two distinct, sequential OS child processes**, checking successful seed exit before reinitialization. Each child constructs a fresh Cordis `Context` and mounts actual rc.2 `SessionStore`, `SessionProjectionRegistry`, shipped JSONL persistence (`compression: none`), and `SessionQueryEngine`. Both use the same isolated native-source directory and the same two private MemoryStore SQLite files: the existing v2 continuity store and a separate fresh-v3 owner store. This is persisted-source/service process reinitialization, **not full main Harness host/Loader/plugin/GUI restart or overall Phase C acceptance**.

The fixture uses the explicit runtime environment `DSH_RUNTIME_RC2=/home/bahman/github/dsh-v0.2`, pins relevant packages to `0.2.0-rc.2` and Zod `4.6.5`, and copies already-emitted workspace `lib` into a private package lane with dependency symlinks. It does not install/patch runtime dependencies or write a profile. Rebuild via `node scripts/typecheck-v02.mjs --emit-lib` before rerunning the fixture after source changes.

## Material cold-header finding and scoped binding v2 fix

The actual cold native decoder hydrates **omitted `delegationDepth` to exactly `0`**. Original live root/fork headers can omit that key. Earlier experimental binding v1 hashed raw header insertion order/representation, so a normal live-captured root could become unusable after native persistence restart despite equivalent immutable ownership. The first version of this fixture exposed that failure; it was not accepted as restart success.

The [scoped checkpoint change](<../src/continuity-checkpoint-v02.ts>) now fingerprints verified native JSON with deterministic recursively sorted object keys and normalizes **only omitted `delegationDepth` to zero**. Present depth values are retained exactly. No parent/origin/cwd/id/createdAt/isSeeded/floor or event field is dropped, no arrays reordered, and neither shared delegation guards nor projection/owner semantics are weakened. Bind and recovery use the same encoding; the source composite is explicitly tagged **`bindingVersion: 2`**.

Existing experimental binding v1 job references fail closed against the new source digest; there is no silent job rebinding, migration or acknowledgment. Old cache envelopes can be rejected and refolded from canonical native events, but this does not authorize rewriting old queued job references or bypass the same-cut conflict guard. Operators cannot interpret cache refolding as existing v1 work becoming resumable. New v2 jobs retain identity across the verified native omitted/default-depth hydration.

This directly exercises native storage and isolated owner persistence; it does not pretend `SessionStore.create` alone attaches the main agent-lifecycle writer or authenticates the synthetic Host-boundary fixtures.

The second child begins with no live sessions. Actual cold observations are `source: prepared`; the only allowed header representation change is omitted depth becoming zero. Original native events, cuts, hash, checkpoint state and inherited floors remain exact. Cache recovery accepts the previous v2 checkpoint; source-reference verification matches it. Reordered object properties also retain the same fingerprint/cache, without treating changed array order or values as equivalent.

Separate checks reject nonzero depth, subagent origin, changed parent/cwd/id/createdAt/isSeeded, changed inherited floor and changed native source data. A genuinely persisted experimental binding v1 cache/job fixture survives the first process exit: its cache refolds, its stored job source reference fails hash admission, and enqueueing the refolded v2 cut hits the same-cut conflict fence. Neither the v1 checkpoint nor the job hash is silently rewritten. An unrelated project cannot read checkpoint/work references. Neither child mounts LlmRuntime/provider adapters, goals, prompt assembly or agent loop. There is no provider/follow/prompt/task execution. The v2 reference store has no work/handoff pair; the v3 fixture creates its worker pair in the seed child, persists one completed handoff with deterministic synthetic text, and in the verify child source-validates and revokes a separate running job plus checks handoff denial after policy revocation. Observation leases, explicit persistence handles and both MemoryStores are closed, and mounted native fibers are disposed before each normal process exit.

## Summary epoch and watermark across processes

In the seed process, the fixture writes an allowed `continuity_summary_policy` epoch and claims the healthy root's body-free human coordinate in `continuity_summary_human`, using the same file-backed MemoryStore as the native continuity references. The verify process sees the allowed epoch, refuses replay, and accepts a later coordinate. It then disables/re-enables consent: disabled state reads as no allowed epoch, claims fail, re-enable increments generation, stale-generation claims remain denied, and a later coordinate is accepted only under the new generation. Against the cold-restored native observation it also checks the watermark's session/project, normalized canonical header hash, inherited floor, and own-user sequence. Current combined results are seed **5/5**, verify **12/12**, distinct child PIDs. These are direct low-level owner calls; they do not load `src/index.ts`, exercise live settings/event callbacks, or prove authenticated human intent/full main-plugin restart.

## Isolated v3 capture owner across processes

A separate `memory-v3` file uses a fresh schema owned by `ensureContinuitySchemaV03`. The seed child writes allowed policies and synthetic fixture-attested live-human boundaries for two roots. It captures an exact-cut pending job for one, and completes the other with `completeWithFreshSource` using a fixed test note (no provider), persisting its body-free checkpoint anchor, pending job, consumed boundary and handoff. The verify child reopens the same file, validates the completed handoff and its note, confirms the captured boundary is consumed, and source-validates a lease for the pending job against cold native JSONL. Revoking the pending-job policy cancels that job, fails its lease and removes its checkpoint; re-enable does not resurrect it or permit stale capture. Revoking the completed-handoff policy makes both current handoff readers return null before/after re-enable, despite the isolated payload row remaining stored. The boundary kind and note are test fixtures, not authenticated Host provenance or provider output. No model execution, user-visible preview/action, production settings/event integration, or full main-plugin restart is exercised.

## Shared ancestry hashing portability (no admission expansion)

The typed exports `continuityCanonicalDigest` and `continuityCanonicalHeader` expose the same audited checkpoint encoding and omitted-depth normalization. Private checkpoint aliases retain the exact binding-v2 bytes. The [standalone ancestry proof](<../src/continuity-ancestry-v02.ts>) now uses those helpers for session/header/source/prefix/proof fingerprints; no ancestry validation, permission guard, projection/fold or main integration was changed.

The first OS child records a live genuine native fork ancestry proof with omitted-depth child and parent headers. After actual persistence/process restart, the second child compares the entire proof—including every header/source/prefix hash and the final proof hash—for exact equality. The same proof remains equal when native cold snapshot objects are recursively reordered. Both acquired native observation leases in that reordered proof are disposed. The seed also builds a detached v3 fork-lineage envelope from the native fork; after restart, the verify child rebuilds it from cold observations and asserts exact equality with the serialized envelope. Only the body-free envelope is saved; raw lineage IDs in the ephemeral snapshot are not persisted. The v3 owner check persists/reopens checkpoint/job/boundary rows, source-validates a lease, and exercises revoke→re-enable cancellation; a second job's completed synthetic handoff is also reopened, then becomes unreadable under revoked policy. No model/provider output, user-visible preview/action, or runtime admission occurs; the fixed note only exercises owner persistence and read gating. Ancestry remains identity-only; inherited-only sources still gain no own-human intent or continuation authority.

## Fork evidence and remaining limitation

A genuine inherited-only native fork is flushed by the first child and cold-observed by the second. Its original inherited-event floor survives, projection `lastHumanSeq` stays `-1`, and no own-human authority, checkpoint or job appears. Its omitted depth likewise hydrates to zero.

The v2 source-reference and shared capture paths remain conservative for any nonempty `parentSession`; this fixture's inherited-only refusal does **not** establish ordinary-fork Continue/recovery acceptance and must not justify weakening Phase A/B guards. Separately, the unregistered v3 projection/ancestry prototype now classifies ordinary native forks only as candidates and validates the full copied-prefix chain before its preview/capture path (see [Continue design](MIGRATION-PHASE-C-CONTINUE-DESIGN.md)). That structural prototype still supplies no authenticated selection intent, action authority or runtime admission; full fork/Continue acceptance remains outstanding.
