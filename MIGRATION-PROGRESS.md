PHASE E STARTED — ACTIVATION SAFETY CORE. Reconnaissance first, because it changed the design: rc.2's skill service exposes `ctx.skills.register(skill)`, which returns **the exact Cordis effect disposer**, and a registration carries a `source: 'runtime'` label plus an invocation policy. That means activation needs NO filesystem write at all — so a learned skill can never overwrite user-authored material, rollback is disposal rather than deletion, and the plugin fiber owning the effect tears it down on unload. [src/skill-activation.ts](src/skill-activation.ts) implements the core: it RENDERS the body itself from structured fields (procedure steps + citations + activation time) so the mandatory provenance header ("activated by the operator", "not permission, and not proof", "verify the current environment") cannot be omitted by a caller and the body stays bounded; it FORCES `{modelInvocable: false, userInvocable: true}` and ignores any caller-supplied policy (a learned skill is invoke-it-yourself, never silently in the model's catalog); it refuses non-kebab names, empty/oversized procedures, oversized descriptions and NULs before anything reaches the registry; it allows one activation per name; and a disposal that throws reports FAILURE and keeps the record rather than claiming a rollback that did not happen. [test-v02-skill-activation.mjs](scripts/test-v02-skill-activation.mjs) pins all six properties (6/6 PASS) with a recording host, so the safety core is verified without a live Cordis context.
